# ADR-0005：自建「Claude 质量门禁」（gate.mjs + githooks + 子代理）

- **状态**：已接受
- **日期**：2026-10（改造时补记）

## 背景

项目用 AI 辅助开发。AI 改代码很快，但也容易「看起来改好了」——
真正的问题（测试没跑、安全疏漏、注释与代码不一致）很容易被漏掉。
需要一种机制，把「提交」这个动作和「检查」绑定起来。

## 决策

自建一套**提交前质量门禁**，由三部分组成：

1. **两个检查子代理**（`.claude/agents/`）：
   - `tester`：跑后端 pytest + 前端 Vitest，全绿后写「单元测试通过票」；
   - `quality-engineer`：做安全审计 / 注释检查 / 其它质量检查，无严重问题后写「质量通过票」。
   - `gitcommit-agent` 是编排者：**并行**派出上述两个子代理，都通过后才提交。
2. **门禁脚本** `scripts/gate.mjs`：写票 / 验票 / 销票 / 装钩子。
   关键设计是**代码指纹**——对所有正式文件内容做 SHA256；**代码在检查之后又改动过，
   指纹就对不上，票自动作废**。
3. **git 钩子**（`.githooks/`，通过 `core.hooksPath` 指向仓库内目录，换电脑不丢）：
   `pre-commit` 调 `gate.mjs check` 验票，不过就拦截提交；
   `post-commit` 调 `gate.mjs reset` **销票**，保证每笔提交都要有当次新鲜的两张票。

## 理由

1. **「验票」比「跑检查」更关键**：Coding agent 很容易在测试通过后又偷偷改一行代码。
   指纹机制让「票」与「被检查的那份代码」严格绑定，堵住这个漏洞。
2. **一提交一销票**：防止 A 的通过票被复用到 B 的提交上。
3. **钩子放在仓库内**（`.githooks/` + `core.hooksPath`）而非 `.git/hooks/`：
   `.git/` 不入库，放里面换个克隆就没了；放仓库内可随代码一起被跟踪与评审。

## 后果

- 优点：提交与检查强绑定、可审计（票是带指纹与时间戳的 JSON）、差异化（面试可讲「我做了什么
  来约束一个 AI 的产出」）。
- 代价与注意事项（**已在 `docs/gate.md` 说明**）：
  - 需要先执行一次 `node scripts/gate.mjs install` 设置 `core.hooksPath`，否则钩子不生效；
  - 紧急情况下可用 `git commit --no-verify` 跳过，但属于例外而非常态；
  - 该机制依赖 Claude 的子代理与技能，属于**辅助工具链**，与业务代码解耦——
    删掉它项目依然可以正常构建与测试（见 `docs/gate.md` 的「与业务的关系」）。

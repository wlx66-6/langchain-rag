## 三、可以主动讲的技术亮点（附「为什么」）

面试官问「你做了什么」时，别罗列功能，讲**决策与取舍**：

1. **SSE 流式输出的三个健壮性设计**
   - 客户端断开检测（`Request.is_disconnected()` + 捕 `CancelledError`）：用户切走就停，不让算力白烧；
   - 生成失败**兜底落库**：保证「用户消息/助手消息」成对，不留悬空记录；
   - **错误脱敏**：SSE 事件只给统一文案 + `code`，真实堆栈只进日志。
   - → 见 [ADR-0004](adr/0004-sse-streaming-and-error-handling.md)

2. **重排及格线兜底逻辑**（这道题很能体现「从数据里发现问题」）
   - 压测时发现：问尺码，系统答「知识库中未找到」，但尺码表明明在库里；
   - 排查：重排给最相关的尺码表只打了 0.1886，低于及格线 0.2，被全部丢弃；
   - 修复：及格线把所有候选筛空时，**强制保留相关度最高的第一名**；
   - → 一句话总结：「宁可多给一条弱相关引用让人自己判断，也不要明明有答案却说找不到。」

3. **JWT 双令牌 + bcrypt 的 72 字节坑**
   - access 30 分钟 / refresh 7 天；令牌内用 `type` 区分，防 refresh 直接访问业务接口；
   - bcrypt 只吃 72 字节，中文密码每字 3 字节 → 先 SHA256 再 bcrypt，避免超长密码被静默截断；
   - `JWT_SECRET` 不设默认值，缺失即启动报错，杜绝「用了弱默认密钥还以为没事」。
   - → 见 [ADR-0003](adr/0003-jwt-dual-token-auth.md)

4. **向量库数据一致性**
   - 删文档要**级联**：删向量块 + 删磁盘物理文件，不留孤儿；
   - `get_vectorstore()` 加进程内缓存，避免每个请求重建 Chroma 实例；
   - 检索去重的 key 从「内容」改成「(来源, 内容)」——两份文档写同一句售后条款是常见的，不该误删引用。

5. **自建质量门禁**（差异化亮点，多数候选人没有）
   - 提交前并行跑「单元测试」+「质量检查」两个子代理，都通过才放行；
   - 关键设计是**代码指纹**：检查后再改代码，通过票自动作废——专门堵「测试通过后偷偷改一行」；
   - `post-commit` 销票，一提交一票，防止复用。
   - → 见 [ADR-0005](adr/0005-claude-quality-gate.md)、[docs/gate.md](gate.md)

6. **工程规范落地**
   - ruff（lint + format）+ ESLint + Prettier + EditorConfig；依赖版本锁定；
   - CI（`scripts/ci.sh` 本地一键复现 + `.github/workflows/ci.yml`）；
   - 用 ADR 记录「为什么不那样做」——面试官问「为什么不用 Postgres/Alembic/Docker」时直接指过去。

## 四、高频追问 & 回答要点

| 问题 | 回答要点 |
|---|---|
| **为什么用 RAG 而不是直接问大模型？** | 大模型不知道「你家的商品资料」，而且会编造。RAG 让它先查资料再回答，**可溯源、防幻觉**。 |
| **引用溯源怎么实现的？** | 检索到的片段按 `[1][2]` 编号写进提示词，要求模型标注出处；后端把片段结构化成 `sources` 随 SSE 的 `start` 事件下发，前端渲染成引用卡片。 |
| **为什么保留 SQLite，不用 Postgres？** | 目标是单机演示/个人项目，SQLite 零部署；并发特征是「少量写 + 多次读」，WAL + busy_timeout 够用。真上生产应换 Postgres + 连接池——**这是取舍不是没做**。见 ADR-0002。 |
| **没有 Alembic，改表怎么办？** | ORM 模型加字段属 schema 变更，开发期删本地 `app.db` 重建（数据可重灌）。为一个演示项目引迁移框架的成本大于收益——已写进 ADR-0002 与 README 的「局限」。 |
| **100 并发 P99 37 秒，这算好吗？** | 不好，我如实写了瓶颈分析：共享线程池被打满（连健康检查都被拖到 4.5s）、bge-m3 单实例 CPU 推理、SQLite 单写者。**能指出瓶颈和优化优先级，比报一个好看的数更有价值**，见压测报告第 5、6 节。 |
| **SSE 和 WebSocket 怎么选？** | 数据流是单向下行，SSE 基于普通 HTTP、无需握手、天然支持断线重连语义，实现和调试都更简单；WebSocket 的双向能力这里用不上。 |
| **前端怎么保证流式不串台？** | `lib/sse.ts` 用 `AbortController` 管理生命周期，切会话/卸载时中止在途流，并用递增序号丢弃过期回调，防止旧流的 token 污染新会话。 |
| **测试怎么保证有效而不是凑数？** | 优先测纯逻辑（脱网、快、稳）；修 bug 先写能复现的失败用例；集成/e2e 用 marker 隔离开，默认跳过、不进 CI，保证 CI 快且稳定。 |

## 五、未实测项与补测方法（如实说明）

**首字延迟（SSE 首个 token 到达时间）未实测。**
原因：实测需要 ① 有效的 `DASHSCOPE_API_KEY`（当前仓库不含 `.env`）② 首次需下载约 2GB 的 bge-m3 模型。

补测方法（配好 `.env` 后执行）：

```bash
# 启动后端后，用 curl 观察首个 data: 事件到达的耗时
curl -N -X POST http://127.0.0.1:8000/api/chat \
  -H "Authorization: Bearer <你的access_token>" \
  -H "Content-Type: application/json" \
  -d '{"content":"这款商品的售后政策是什么？","conversation_id":null}' \
  -w '\n---\n首字耗时可用 curl 的 time_starttransfer 观察，或加 -s -o /dev/null -w "%{time_starttransfer}"\n'
```

> 提示：首字延迟 ≈ 向量化 + 检索 + 重排的耗时；**它衡量的是「系统在模型开始吐字前花了多久」**，
> 与总时长（2.9s）不是一回事。

## 六、演示步骤（面试现场或录屏）

1. `start.bat` 启动 → 浏览器打开 http://localhost:5173
2. 注册普通用户 → 登录 → 确认**看不到**「知识库」入口（权限隔离）
3. 用配置在 `.env` 里的管理员账号登录 → 上传一份商品 PDF → 显示「已入库」
4. 提问「这款商品的售后政策是什么？」→ 观察**流式吐字** + 下方**引用卡片**
5. 追问「那它有几种颜色？」→ 验证多轮上下文改写生效
6. 新建会话 / 切换会话 → 验证会话隔离；退出重登 → 验证历史持久化
7. （可选）打开 http://127.0.0.1:8000/docs 展示自动生成的接口文档
8. （可选）展示 `bash scripts/ci.sh` 全绿 + `docs/adr/` 的决策记录

## 七、这个项目的边界（主动说，比被问出来好）

- 单机部署、未容器化；SQLite 不适合高并发写；无数据库迁移工具；
- 向量化是单实例 CPU 推理，是并发下的主要瓶颈；外部 API 无超时/重试/限流；
- 未实现 refresh token 的服务端吊销（登出为前端丢弃令牌）；
- 无 i18n / 深色模式 / 细粒度权限模型（有意不做，避免范围蔓延）。

完整清单见 [README「局限与展望」](../README.md)。

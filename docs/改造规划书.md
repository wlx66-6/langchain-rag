# 项目改造规划书 —— 电商知识库问答系统（LangChain RAG）

> 本规划书的目标：把一个「跟着黑马程序员网课敲出来」的课程作业，改造为**可用于求职简历**的规范、成熟项目。
>
> **本文档位置**：`docs/改造规划书.md`。改造过程中若范围有变，同步更新本文档。

---

## 一、背景与目标（Context）

**现状**：项目是一个功能完整的 RAG 问答系统（FastAPI + LangChain + ChromaDB + 本地 bge-m3 + 通义千问/百炼重排 + React 18/TS/Vite），已有 61 项单测、Locust 压测、以及一套自建的「Claude 质量门禁」工具链。功能不缺，但**充满课程作业痕迹**，且存在若干真实缺陷。

**问题**：
- 代码里有真实 bug（SSE 泄漏异常信息、前端流式请求无取消、上传无大小限制、静默吞异常全覆盖）。
- 工程化缺位（依赖无版本锁定、无 lint/format、无 CI、无 LICENSE）。
- 文案与数据有「答辩/毕设/网课味」（README 有"答辩要点提示"、示例数据用"星辰X1蓝牙耳机"、提交信息写"自黑马记账迁移"）。
- 仓库卫生问题（~2MB 压测生成物被 git 跟踪、`test-report.md` 生成物入库）。

**目标**：改造后，项目**对外看起来是一份正常的、有工程素养的独立项目**；对面试官，每个技术点都能讲清「为什么这么做」；且能拿出发言有据的量化数字（测试数、覆盖率、接口数、首字延迟、压测指标）。

**已确认的方向（不再变更）**：

| 决策项 | 结论 |
|---|---|
| 主要用途 | **求职简历**（AI 应用 / 后端开发岗） |
| 改造深度 | **精修打磨**——保持现有架构，不推倒重来 |
| 数据库/部署 | **保留 SQLite**，不迁 Postgres、不引入 Docker |
| Claude 质量门禁工具链 | **保留 + 修缺口 + 补文档**（差异化亮点） |
| 注释语言 | **保留中文**（面向国内招聘） |

## 二、改造原则与范围边界

**原则**：
1. **保持架构**：分层的 `routers / services / core / models` 与前端页面结构不动，只做局部重构（抽 SSE 工具、抽类型、拆 CSS）。
2. **先测试，后改逻辑**：给将被修改的模块先加"回归安全网"，避免修 A 坏 B。
3. **先卫生，后包装**：仓库/安全清理排在文档重写之前。
4. **可回退**：每阶段一条分支，每个任务一个独立 commit，阶段末打 tag。
5. **诚实**：README 与压测报告里的数字必须与实测一致，删掉所有夸大表述。

**本次明确不做（防范围蔓延）**：
- ❌ 不迁 PostgreSQL、不引入 Alembic 迁移框架
- ❌ 不引入 Docker / docker-compose
- ❌ 不全面重构前端（不引 Tailwind、不引组件库、不重写页面）
- ❌ 不改写 git 历史（网课痕迹用 CHANGELOG 说明）
- ❌ 不引入微服务 / Celery / 消息中间件
- ❌ 不做 i18n、深色模式、细粒度权限模型
- ❌ 不把真实 LLM 集成测试放进 CI（成本/稳定性）

## 四、分阶段改造计划

> 排序理由（回答"先修 bug 还是先补测试"）：**先补测试再改逻辑**——20+ 处后端缺陷几乎都在**没有路由级测试**的模块里，无回归网直接改逻辑，修 A 坏 B 不可察觉。**先统一风格再写文档**——文档必须描述代码最终形态；但工具配置早建、全量格式化晚做且单独提交。

| 阶段 | 名称 | 目标 | 依赖 |
|---|---|---|---|
| **P1** | 仓库卫生与安全基线 | 不改逻辑，清除污染源与泄漏 | — |
| **P2** | 测试安全网 | 建回归保护 + 覆盖率基线 | P1 |
| **P3** | 后端正确性与健壮性 | 修全部后端 bug + 日志/并发加固 | P2 |
| **P4** | 前端正确性与健壮性 | 修 SSE 生命周期/鉴权/交互 | P2（可与 P3 并行） |
| **P5** | 工程化与工具链 | ruff/ESLint/CI/依赖锁定 + 修 Claude 工具链 | P3、P4 |
| **P6** | 文档与简历包装 | README/许可证/接口文档/压测报告 | P5 |
| **P7** | 量化与演示物料（可选） | 实测数字、面试速览 | P6 |

## 六、代码风格与注释规范

**Python（用 ruff 统一，不单独引 black）**
- `ruff check`（lint）+ `ruff format`（格式化）。规则集 `E, F, I, UP, B, SIM`；行宽 100；target `py310`。
- 命名：函数/变量 `snake_case`，类 `PascalCase`，常量 `UPPER_SNAKE`，私有前缀 `_`。
- docstring：模块首行中文一句话；公共函数（router 端点、service 公开函数、`core`）用 Google 风格（`Args`/`Returns`/`Raises`）；私有函数一句话或不写。
- 类型注解：公共函数参数与返回值必须标注。
- 注释准则：**写"为什么"，不写"是什么"**。该写的地方如：`database.py` 为何 `check_same_thread=False`；`chat.py` 为何独立 Session 落库；`loader.py` 编码策略。禁止注释掉的死代码、禁止复述代码的注释。

**前端（ESLint + Prettier）**
- ESLint：`typescript-eslint`(recommended) + `react-hooks` + `react-refresh`；`no-explicit-any` 设 warn 并逐步升 error。
- Prettier：`printWidth 100`、`singleQuote`、`semi` 先跑一次看现状再定；作为唯一格式化来源。
- tsconfig：打开 `noUnusedLocals`、`noUnusedParameters`。
- 命名：组件 `PascalCase`，hook `useXxx`，工具 `camelCase`，类型 `PascalCase`，常量 `UPPER_SNAKE`。
- 错误处理：`catch (e: unknown)` + 类型守卫，不空吞。

**提交约定**：Conventional Commits（`fix:`/`refactor:`/`style:`/`test:`/`docs:`/`chore:`）；"全量格式化"单独 `style:` commit。

## 九、风险与回滚

**回退粒度**：每阶段一条分支 + 每任务一个独立 commit + 阶段末打 tag（`v0.2-hygiene`、`v0.3-testnet` …）；回退粒度 = 单 commit。

**高风险项各自单独 commit**：P5.3 全量格式化（可整体 revert）、P1.1 生成物移除（涉及 `git rm --cached`）、P3.4 `models.py` 加字段（涉及 schema）。

**主要风险**
1. **schema 变更无迁移工具** → dev 重建数据库 + README 如实说明；不引 Alembic。
2. **测试锁住 buggy 行为**（P2 的 `_dedup`/SSE error 断言）→ P3 必须同步改断言，commit message 显式标注"测试随修复更新"，否则 CI 假绿。
3. **格式化 diff 淹没逻辑** → 逻辑先行、格式化后置且独立 commit。
4. **改 git 历史风险高** → 不做，用 CHANGELOG 说明。
5. **前后端分页契约变更**可能 breaking → 加默认值保持兼容，前端 P4 同步。

# 电商知识库问答系统（LangChain RAG）

一个基于 **LangChain** 框架的企业级知识库问答系统，面向电商商品场景。用户通过浏览器上传商品资料构建知识库，然后像和客服聊天一样提问，系统会**先检索知识库、再生成回答，并在回答中标注引用了哪些资料片段**——保证回答有据可查、不瞎编。

> 一句话概括：**一个「会先翻资料、再回答、还标注出处」的智能客服。**

## 一、核心功能

| 需求 | 实现 |
|---|---|
| 浏览器知识库管理 | 管理员上传/删除/查看 PDF、Word、Excel、TXT、Markdown、CSV 文档 |
| 问答并引用出处 | 回答下方展示「引用资料」，含来源文件名和片段内容 |
| 多用户多会话 | 每个用户可开多个会话，互不串扰 |
| 会话记录持久化 | 历史对话存库，随时登录找回、继续聊 |
| 注册/登录/改密码 | 密码 bcrypt 加密存储 + JWT 令牌鉴权 + 刷新令牌 |
| 管理员权限隔离 | admin/123456 唯一能进知识库管理，普通用户只能问答（前端路由 + 后端双重校验） |
| 企业级优化 | 流式输出(SSE)、追问改写、检索+生成编排、数据库连接池、.env 密钥管理等 |
| 加分项 | Markdown 渲染、引用卡片、多轮上下文理解 |

## 二、技术选型

| 部件 | 选型 |
|---|---|
| 开发框架 | LangChain（Python） |
| 后端 | Python + FastAPI |
| 大模型 | 阿里云百炼（通义千问 Qwen，默认 qwen-plus） |
| 向量化模型 | 本地 bge-m3（免费、中文效果好） |
| 向量数据库 | ChromaDB（本地持久化） |
| 结构化数据库 | SQLite + SQLAlchemy |
| 前端 | React 18 + TypeScript + Vite |

## 三、工作原理（大白话版）

```
浏览器(React) ──HTTP/SSE──> FastAPI 后端
                              ├─ 用户/会话 ──> SQLite
                              ├─ 文档解析 → 切块 → bge-m3 向量化 → ChromaDB
                              └─ 检索(ChromaDB) → 通义千问生成 → 带引用返回
```

问答流程：**问题 → 用 bge-m3 把问题变成「指纹」→ 去 ChromaDB 找最相关的几段 → 拼给通义千问 → 生成回答并标注 [编号] 出处 → 前端高亮显示引用片段**。

## 四、快速开始（Windows）

### 第 0 步：准备工作
1. 安装 [Python 3.10+](https://www.python.org/)（勾选 *Add to PATH*）
2. 安装 [Node.js](https://nodejs.org/)
3. 注册[阿里云百炼平台](https://bailian.console.aliyun.com/)，开通通义千问，获取 **API Key**

### 第 1 步：配置密钥
编辑 `backend\.env`，填入你的百炼 API Key：
```
DASHSCOPE_API_KEY=你的密钥
```

### 第 2 步：一键安装
双击项目根目录的 **`setup.bat`**（首次运行，自动创建虚拟环境 + 安装前后端依赖）。

### 第 3 步：一键启动
双击 **`start.bat`**，会自动拉起后端(8000端口)和前端(5173端口)，并打开浏览器。

> 打开浏览器访问 **http://localhost:5173** 即可。

### 手动启动（可选）
```bash
# 后端
cd backend
..\venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# 前端（另开一个终端）
cd frontend
npm run dev
```

## 五、使用与自测清单

1. 注册一个普通用户 → 登录 → 能进聊天页，但**看不到**「知识库」入口
2. 用 **admin / 123456** 登录 → 能看到「知识库」入口，上传几份商品 PDF/Word → 显示「已入库」
3. 提问「这款商品的售后政策是什么？」→ 得到回答，且**下方显示引用的知识库片段**
4. 追问「那它有几种颜色？」→ 能结合上文正确回答（多轮上下文理解）
5. 退出重新登录 → 历史会话还在
6. 换一个账号登录 → 只看到自己的会话（相互隔离）

## 六、常见问题

- **首次提问/上传很慢？** 首次会自动下载 bge-m3 模型（约 2GB），之后就好了。国内网络已默认走 hf-mirror 镜像加速。
- **提示 API Key 无效？** 检查 `backend\.env` 里的密钥，以及百炼平台是否已开通通义千问。
- **端口被占用？** 修改 `start.bat` 里的 `--port` 和 `vite.config.ts` 里的端口即可。
- **想换更强/更便宜的模型？** 改 `backend\.env` 里的 `QWEN_MODEL`（qwen-turbo / qwen-plus / qwen-max）。

## 七、答辩要点提示

- **为什么用 RAG**：大模型本身不知道「你家的商品资料」，且会编造；RAG 让大模型「先查资料再回答」，回答可溯源、防幻觉。
- **引用溯源怎么实现**：检索到的片段按 [1][2] 编号写入提示词，要求模型标注出处，前端再展示对应片段。
- **企业级优化体现在哪**：流式输出提升体验、追问改写理解上下文、检索+生成解耦、密钥不入库(http 环境变量)、数据库连接池、前后端分离等。
